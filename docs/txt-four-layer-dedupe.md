# TXT 四层去重改造方案

## 目标与范围

直接增强桌面程序和 CLI 的 TXT 扫描。Windows 用户选择小说目录、启用 TXT 后即可运行，不需要先导出文件名或复制数据到 Mac。文件名清单只用于验证解析规则。图片、视频判定保持现有行为。

## 四层证据

1. **原始文件一致**：保留大小分桶、采样预筛和完整 SHA-256 确认；TXT 永远不能仅凭采样判为精确重复。文件名不参与否决。
2. **文本一致**：严格解码 UTF-8/BOM、UTF-16 BOM、GB18030，将 CRLF/CR 统一成 LF 后计算文本 SHA-256。保留大小写、标点、空白数量、广告和段落，避免有损清洗制造一致。空文本不构造新的近似证据。原始哈希不同、文本哈希相同的记录展示为“TXT 文本一致”。
3. **正文近似与包含**：正文指纹独立召回，与书名候选取并集。使用相同哈希截断位置比较 bottom-k 指纹，估计双向覆盖率；整体相似与单向包含分别判断，包含不再受旧的 70% 长度比阻断。保持最低证据数量；短文本或样本不足不推断包含。名称相似不再把正文阈值降至 0.62。近似、包含均需人工核对，不自动删除。
4. **名称关联**：共享解析器提取核心书名、明确别名、作者、章节/分册、版本、来源与歧义。去掉网址及包装，但不丢弃用于版本判断的信息。精确书名和别名优先，较长书名的严格模糊匹配用于补充。纯数字、短书名、含糊副本序号以及作者/版本冲突降级。仅名称证据不显示为正文相似，不自动删除。

## 名称解析规则

- 保留原文件名；匹配时统一 NFKC、大小写和书名外围标点，连续 `.txt` 扩展名统一处理。
- 识别 `域名@书名`、粘连的 `书名www.example.com`、括号域名、来源标签；域名前章节不能被正则吞掉。
- 在完整名称中先收集作者、章节和版本，再截取书名。作者后的 `[上]`、`[下]` 仍属于分册。
- 识别阿拉伯/中文数字范围、全半角连接符、前后置章节、明确更新进度；卷与章不能直接换算。单个裸数字、复合卷章、缺失括号保留歧义。
- 保留 `2035`、`2012`、书名中的 `2`；前传、续作、番外、改版、同人、上中下不视为普通噪声。
- 作者未标注/不详不形成作者冲突；明确不同作者、不同版本或互补章节会显示冲突/关系提示，不作为可替代的依据。

## 分组和动作

- 原始精确组保留代表继续参与 TXT 比较；同文本哈希的副本也只需一个代表参与较重比较，随后恢复成员。
- 关联组只是浏览容器。每项理由明确指向实际比较的文件，分别描述正文相似、覆盖、章节互补或仅名称关联；A–B、B–C 不意味着 A–C 重复。
- 纯文本一致组可以推荐保留一个，其余为确定的文本副本。混合关联组中的非等价文件为“待核对”；对照文件不意味着它能替代其他文件。
- 自动勾选、按组批量删除和可释放空间统一只使用 `cleanup_candidate`；待核对项必须人工选择。更换对照文件不能把待核对项改成清理候选。
- 确定的原始/文本副本并入关联组时保留明确理由；默认清理只处理确定副本，保留每个等价类别的代表。

## 缓存、性能和兼容

- 新增文本指纹数据结构及文本哈希缓存，提升算法版本使旧指纹自动失效。名称由当前路径重新解析，不将旧的名称键继续作为真值。
- 指纹特征数量保持有界；中文名称索引只使用核心书名的有用片段，不用 `作者`、公共章号作索引。
- TXT 扫描支持取消；顺序输出与稳定排序保证冷扫/缓存重扫一致。
- 现有 SQLite 缓存就地升级；新增字段迁移失败必须报告，不隐藏失败。
- 桌面结果、筛选、导出报告同步认识新增类型。保留原始精确组与已有媒体类型兼容性。

## 实施顺序

1. 名称解析器与保守文本解码/规范化；构造本地单元和反例场景。
2. 文本哈希缓存、正确的指纹覆盖比较、候选召回及分组证据。
3. Pipeline 精确副本融合、动作不变量、缓存推荐项更新。
4. 桌面展示、筛选、默认勾选、批量操作和导出说明。
5. 全量 Go 测试/构建/vet、前端类型检查和构建；真实目录的合成 TXT 冷扫/重扫、Windows 交叉编译、浏览器界面验证。
6. 独立 review，修复问题并复验。提交中文 commit，推送 main，发布新的语义化版本 tag，核对 GitHub Actions 与 Windows 发布包。

## 验收场景

- 改名但字节相同；采样相同但中部不同的大 TXT 不能精确命中。
- UTF-8/GB18030/UTF-16、BOM 和换行不同而文本一致；大小写、标点、空白、广告不同不能误判为文本一致；非法编码不能变成一致文本。
- 相同/不同书名的正文近似；噪声包装、粘连网址、作者后的分册、重复扩展名、数字书名、前传和改版。
- 1–50 与 1–200 的正文包含；1–70 与 71–100 互补；1–100 与 80–150 部分重叠；裸书名不是全集。
- 低内容多样性和短文本不产生高置信包含；没有足够指纹时只保留名称候选。
- 已确认副本和第三个相关版本同时存在；链式相似不自动清理；作者未知不能把两个明确不同作者的作品判为等价。
- 缓存升级、冷扫/热扫一致、取消扫描；更换推荐项、文件缺失和重新扫描不把 review 升为 cleanup。
- GUI 默认不勾选待核对文件；后端按组展开与可释放空间采用同一个动作规则。

本地临时测试遵循仓库约定，不强制加入 Git；真实 5 GB 小说由用户在 Windows 上进行最终实测。
