# 媒体去重工具第一版设计

## 背景与目标

本项目要构建一个本地运行的 Python 命令行媒体去重工具。用户输入一个或多个目录，工具递归扫描其中的视频和图片文件，找出完全重复或视觉上相似的媒体，并给出“推荐保留哪个文件”的可解释建议。

第一版定位为整理辅助工具，而不是自动清理工具。它会生成报告、分组和保留建议，但不会自动删除文件。这样可以先验证算法准确率，降低误删照片和视频的风险。

目标使用场景是中型媒体库：几万到十几万个文件。设计必须支持 SQLite 缓存、增量扫描、候选分桶和失败文件记录，避免每次运行都重新计算所有媒体指纹。

## 已确认的产品选择

- 使用方式：Python/uv 命令行工具。
- 数据规模：中型媒体库，几万到十几万个文件。
- 工作模式：整理辅助型，输出推荐保留和清理候选。
- 保留策略：质量优先。
- 检测路线：分层检测，从便宜信号逐步进入昂贵的视觉指纹计算。
- 第一版安全边界：不自动删除，不做 GUI，不做云端扫描。

## 非目标

第一版明确不做以下事情：

- 自动删除、强制移动或静默修改用户文件。
- 图形界面、桌面应用或本地 Web UI。
- 云端扫描、远程索引或多人协作。
- 图片与视频之间的跨类型比较。
- 语义级相似检测，例如两个不同视频都拍摄同一个地点。
- embedding、FAISS、深度学习聚类等高级检索能力。
- 对严重裁剪、拼接、镜像、强水印的复杂鲁棒识别。

## 整体架构

第一版采用“CLI + SQLite 缓存 + 分层检测流水线”的架构。

### CLI 层

CLI 负责解析命令、参数、输出格式和运行模式。核心命令包括：

- `scan DIR...`：扫描一个或多个目录，计算或复用缓存，生成重复组和报告。
- `report`：不重新扫描，读取上次扫描结果并重新输出报告。
- `cache info` / `cache clear`：查看或清理缓存。
- `doctor`：检查 Python 运行环境、Python 包依赖和 `ffmpeg` / `ffprobe` 可用性。

### 文件发现层

文件发现层递归扫描输入目录，识别图片和视频文件，并记录每个文件的基础状态。

默认图片扩展名包括：`jpg`、`jpeg`、`png`、`webp`、`heic`、`heif`、`tiff`、`bmp`、`gif`。

默认视频扩展名包括：`mp4`、`mov`、`mkv`、`avi`、`webm`、`m4v`、`flv`、`wmv`、`mpeg`、`mpg`。

默认跳过 `.git`、`.venv`、常见系统缓存、隐藏目录、损坏软链和重复路径。每个文件记录路径、大小、mtime、inode、扩展名和媒体类型。

### 指纹计算层

指纹计算层负责提取后续比较需要的事实数据：

- 精确指纹：文件大小、快速 hash、完整 hash。
- 图片指纹：pHash、dHash 或 wHash 等感知 hash。
- 视频元数据：时长、分辨率、帧率、码率、编码格式和可解析状态。
- 视频视觉指纹：多个时间点抽帧，每帧计算感知 hash。

这些事实数据写入 SQLite。文件未变化时直接复用缓存。

### 候选生成层

候选生成层负责减少比较规模，避免全量两两比较。它根据媒体类型、文件大小、图片尺寸、视频时长、宽高比例、hash 前缀和弱文件名信号做分桶。

这一层只决定“哪些文件值得继续比较”，不直接判断重复。

### 相似度与分组层

相似度层判断两个文件是否相似：

- 完全重复：完整内容 hash 一致，置信度为 1.00。
- 图片相似：根据感知 hash 的汉明距离转换为相似度。
- 视频相似：根据多帧感知 hash 的中位数距离或多数帧匹配比例转换为相似度。

默认相似度阈值为 `0.80`。达到阈值的文件对形成相似边，最终通过连通分量合并成重复组。

### 质量评分与报告层

质量评分层只解决“同组里推荐保留哪个”。它不参与判断两个文件是否相似。

报告层输出每个重复组、组内文件、相似度、质量分、推荐保留文件、清理候选和推荐理由。

关键原则是：检测是否相似与决定保留哪个必须分开。前者靠相似度算法，后者靠质量评分。

## 检测流水线

检测按从便宜到昂贵的顺序执行。

### 第 0 层：文件发现

扫描输入目录，过滤出支持的图片和视频文件。对每个文件记录基础状态，并用路径、大小、mtime 和 inode 判断是否可复用缓存。

### 第 1 层：完全重复检测

先按文件大小分桶。文件大小唯一的文件可以延迟计算完整 hash；同大小文件超过一个时再计算完整 hash。完整 hash 一致的文件判定为字节级完全重复。

这类结果置信度最高，可以直接进入 exact duplicate 组。

### 第 2 层：元数据候选生成

图片候选条件：

- 宽高接近。
- 文件大小比例没有明显异常。
- 扩展名不作为硬条件，允许 `jpg` 与 `png` 等不同格式进入候选。

视频候选条件：

- 时长接近，默认容忍 ±5% 或 ±3 秒。
- 宽高比例接近。
- 文件大小比例只作为弱信号，因为重编码可能显著改变大小。
- 文件名相似度只作为弱信号，不作为硬条件。

元数据只用于候选筛选，不用于最终重复判定。

### 第 3 层：图片相似检测

图片默认使用 pHash。pHash 在速度、稳定性和实现复杂度之间较平衡。后续可以增加 dHash、wHash 或 crop-resistant hash 做高级模式。

比较时以 hash 汉明距离作为内部指标，再转换成报告里的相似度百分比。默认只展示相似度达到 `0.80` 及以上的结果。

第一版对裁剪、强水印、镜像和大幅构图变化只做有限支持，不承诺完全识别。

### 第 4 层：视频相似检测

视频侧使用 `ffprobe` 提取元数据，使用 `ffmpeg` 或兼容后端抽帧。默认抽取 8 到 10 帧，位置可以是 5%、15%、25% 到 95% 一类的均匀时间点。

抽帧后对每帧计算感知 hash。黑屏、纯色、低方差帧应跳过，以减少片头、片尾、转场造成的误判。

视频比较不只用平均距离。默认使用多帧 hash 距离的中位数，或使用“多数帧匹配比例”作为判定依据。这样少量不同片段不会过度影响整体结果。

如果两个视频时长差距明显超出容忍范围，默认不进入视频视觉指纹比较，除非用户启用宽松模式。

### 第 5 层：重复分组

相似判断产生文件对之间的边。分组层将相似边合并为连通分量，形成重复组。

组类型包括：

- `exact`：字节级完全重复。
- `similar_image`：图片近似重复。
- `similar_video`：视频近似重复。

报告中可以用置信区间辅助理解：

- `exact`：1.00。
- `high`：0.90 及以上。
- `medium`：0.80 到 0.90。

低于默认阈值的候选默认不展示。

## SQLite 缓存与增量扫描

SQLite 缓存用于保存事实数据、扫描记录、错误和报告结果。事实数据与报告结果分开保存，便于改阈值后复用已有指纹。

### `files`

记录文件索引：

- `id`
- `path`
- `media_type`
- `extension`
- `size_bytes`
- `mtime_ns`
- `inode`
- `device`
- `status`
- `last_seen_at`

用途是判断文件是否变化、是否移动、是否仍存在，以及是否可以复用已有计算结果。

### `file_hashes`

记录精确 hash：

- `file_id`
- `size_bytes`
- `quick_hash`
- `full_hash`
- `hash_algorithm`

完整 hash 可以按需计算，避免对明显唯一大小的文件做不必要 IO。

### `media_metadata`

记录图片和视频的基础媒体信息。

图片字段包括宽、高、格式、EXIF 方向和可读状态。

视频字段包括时长、宽、高、帧率、码率、编码格式、音频信息和可解析状态。

### `perceptual_hashes`

记录图片和视频帧的感知 hash。

图片记录：

- `file_id`
- `hash_type`
- `hash_value`
- `hash_size`

视频记录：

- `file_id`
- `frame_index`
- `timestamp_ms`
- `hash_type`
- `hash_value`
- `frame_quality`
- `decoder`

视频记录 decoder 和 frame quality，方便排查抽帧失败、黑屏帧和不同解码后端差异。

### `duplicate_groups` 与 `duplicate_items`

记录扫描结果：

- 组类型。
- 组置信度。
- 推荐保留文件。
- 组内文件相似度。
- 组内文件质量分。
- 推荐动作。
- 推荐理由。

`report` 命令读取这些表即可重新生成报告，不需要重新扫描。

### `scan_runs` 与 `errors`

记录每次扫描的输入目录、参数配置、开始和结束时间、文件数量、成功数量、失败数量和错误文件。

损坏文件、权限不足文件、无法解析的视频和抽帧失败不应让整次扫描失败，应进入错误表并在报告中展示。

### 增量扫描逻辑

每次 `scan DIR...` 的流程：

1. 发现所有候选媒体文件。
2. 用 path、size、mtime 和 inode 判断缓存命中。
3. 未变化文件复用旧 metadata、hash 和 fingerprint。
4. 新文件或变化文件重新计算事实数据。
5. 本次没有再次出现的文件标记为 `missing`，不立即删除缓存。
6. 根据本次参数重新生成 duplicate groups。

缓存保存事实，报告保存某次参数下的结果。这能让后续调整阈值时尽量复用已有计算。

## 质量评分与推荐保留

质量评分只在同一个重复组内部比较，目标是推荐保留最值得保存的文件。

### 图片质量评分

图片评分维度包括：

- 有效分辨率：宽乘高越大越好，但差距很小时不应过度拉分。
- 格式优先级：无损或高质量格式略加分，但不能简单认为 PNG 一定优于 JPG。
- 文件完整性：能正常打开、无截断、无明显损坏的文件优先。
- 文件大小合理性：同分辨率下过小可能是强压缩，过大只做轻微加分。
- 路径和文件名弱信号：例如 `original`、`raw`、`camera` 可作为平局处理，不压过分辨率和完整性。

### 视频质量评分

视频评分维度包括：

- 分辨率：4K、1080p、720p 等更高分辨率优先。
- 时长完整性：同组内明显短很多的视频降权，完整时长优先。
- 码率：同分辨率下较高码率通常更好，但只做区间评分。
- 编码格式与容器：兼容性好的常见格式略加分。
- 可解析性：`ffprobe` 成功、关键元数据完整、抽帧成功率高的文件优先。
- 音频和字幕信息：第一版可以展示，默认只做轻量评分信号。

### 推荐动作

组内文件动作包括：

- `keep_recommended`：推荐保留。
- `cleanup_candidate`：建议清理候选。
- `review_required`：相似度较高但质量分接近，或存在异常，需要人工确认。

第一版不做自动删除。后续可以增加 `move --to DIR` 或 `trash`，但仍应避免硬删除。

### 推荐理由

报告必须给出可读原因，而不是只给分数。例如：

```text
推荐保留: IMG_001_original.jpg
原因:
- 分辨率最高: 4032x3024
- 文件可正常读取
- 与其他 2 个文件相似度 0.94+
- 其他文件分辨率较低或压缩更强
```

视频示例：

```text
推荐保留: movie_1080p_h264.mp4
原因:
- 分辨率最高: 1920x1080
- 时长完整: 01:42:13
- 抽帧成功率 100%
- 码率高于同组其他文件
```

## CLI 与输出报告

### `scan`

主命令示例：

```bash
uv run media-dedupe scan ~/Pictures ~/Movies
```

常用参数：

```bash
--similarity 0.80
--workers 4
--cache .media-dedupe/cache.sqlite
--output reports/
--format text,json,html
--no-video
--no-image
--recursive / --no-recursive
```

`scan` 负责扫描目录、计算或复用缓存、生成重复组和输出报告。

### `report`

示例：

```bash
uv run media-dedupe report --format html
```

`report` 不重新扫描，只读取上次扫描结果并重新生成 text、JSON 或 HTML 报告。

### `cache`

示例：

```bash
uv run media-dedupe cache info
uv run media-dedupe cache clear
```

`cache` 负责查看缓存大小、文件数、上次扫描时间，以及清理缓存。

### `doctor`

示例：

```bash
uv run media-dedupe doctor
```

`doctor` 检查 Python 版本、Python 包依赖、`ffmpeg` 和 `ffprobe`。如果视频能力不可用，应给出明确提示，例如 macOS 可通过 Homebrew 安装 ffmpeg。

### 报告格式

第一版至少支持 text 和 JSON。HTML 可以作为增强项加入，但不承诺浏览器内删除操作。

text 报告适合终端快速查看：

```text
Group #12 similar_video confidence=0.91
Recommended keep:
  /Movies/A/movie_1080p.mp4
  reason: higher resolution, complete duration, higher bitrate

Cleanup candidates:
  /Downloads/movie_copy_720p.mp4
  similarity: 0.91
  reason: lower resolution, lower bitrate
```

JSON 报告适合脚本处理：

```json
{
  "groups": [
    {
      "type": "similar_video",
      "confidence": 0.91,
      "recommended_keep": "...",
      "items": [
        {
          "path": "...",
          "action": "keep_recommended",
          "similarity": 1.0,
          "quality_score": 0.92,
          "reasons": ["higher resolution", "complete duration"]
        }
      ]
    }
  ]
}
```

HTML 报告如果实现，应以分组卡片、缩略图、推荐保留高亮和清理候选列表为主。

## 第一版范围

第一版包含：

- 多目录递归扫描。
- 图片和视频识别。
- 字节级完全重复检测。
- 图片 pHash 相似检测。
- 视频 `ffprobe` 元数据提取。
- 视频多时间点抽帧和感知 hash。
- SQLite 缓存和增量扫描。
- 相似组生成。
- 质量优先推荐保留。
- text 和 JSON 报告。
- `doctor` 环境检查。
- 核心逻辑测试。

第一版不包含：

- 自动删除。
- GUI。
- 云端或远程扫描。
- 图片和视频互相比。
- 语义级相似。
- 高级 embedding 或 FAISS 检索。
- 复杂裁剪、拼接、镜像、强水印鲁棒识别。

## 测试策略

测试分三层。

### 纯逻辑单元测试

覆盖文件分桶、相似度换算、质量评分、分组算法和缓存命中判断。

### 小样本集成测试

使用少量重复、压缩、改尺寸图片，以及短视频样本，验证扫描能产出预期重复组。

### 环境测试

覆盖 `doctor` 在没有 ffmpeg 时给出清晰提示、损坏文件不会让扫描崩溃、权限不足文件进入错误记录。

## 推荐实现顺序

1. CLI 和文件发现。
2. SQLite schema 和缓存命中。
3. exact duplicate 检测。
4. 图片相似检测。
5. 视频元数据和抽帧指纹。
6. 分组和质量评分。
7. text 和 JSON 报告。
8. `doctor` 和测试。

## 设计风险与缓解

### Python 3.14 依赖兼容性

当前项目要求 `requires-python = ">=3.14"`。部分媒体库可能尚未完整声明支持 Python 3.14。实现前需要通过 `uv add` 和最小导入测试确认依赖可用性。若关键库不支持，应优先选择纯 Python 或维护活跃的替代方案，必要时再讨论是否放宽 Python 版本。

### ffmpeg 系统依赖

视频去重依赖 `ffmpeg` 和 `ffprobe`。第一版必须提供 `doctor` 命令，在扫描前检查依赖，并对缺失依赖给出清晰安装提示。

### 误判风险

默认不自动删除，且报告给出相似度、质量分和推荐理由。相似度处于中等区间或质量分接近的组应标为 `review_required`。

### 性能风险

视频抽帧是主要瓶颈。通过 SQLite 缓存、候选分桶、低方差帧跳过、可配置 worker 数和按需完整 hash 计算降低重复工作。
